# M6-06 – Produktivmodus lädt eigene Daten und Live-Kurse aus Streamlit-Secrets

[GitHub #91](https://github.com/FelixSchramm/stock_treemap_open_ai/issues/91)

Epic: #6 (M6)

**Priorität:** P0 · **Größe:** M · **Art:** Umsetzung

## Ziel

Nach erfolgreicher Besitzerprüfung zeigt der Produktivmodus das eigene Depot aus dem Sheet mit Live-Kursen für die vom Besitzer geprüften Listings, statt der Demo. Der Betrieb auf Streamlit Community Cloud (#30) funktioniert ohne Dateien: Service-Account-Schlüssel und Listings kommen aus den serverseitigen Secrets.

## Ausgangslage

- `app.py` zeigt im Produktivmodus nach der Freigabe nur die Demo („Echte Daten sind noch nicht verfügbar“).
- `PORTFOLIO_SHEETS_CREDENTIALS_FILE` erwartet einen Dateipfad; Community Cloud kann keine Dateien bereitstellen, nur Secrets (TOML).
- Live-Kurse gibt es bisher nur im lokalen Modus über `PORTFOLIO_LISTINGS_FILE` (PR #68).

## Umsetzung

- Produktivmodus: nach `require_owner` denselben Ladeablauf wie im lokalen Modus nutzen (Sheet, Listings, `QuoteCache`, `YFinanceProvider`), einmal pro Sitzung aufgebaut.
- Service-Account aus dem Secret-Abschnitt `[sheets_service_account]` lesen (gleicher Read-only-Scope, neutrale Fehlermeldungen); `PORTFOLIO_SHEETS_CREDENTIALS_FILE` gilt nur noch im lokalen Modus.
- Listings aus `[[listing]]`-Einträgen der Secrets lesen, gleiches Format und gleiche Prüfung wie `listings.toml`.
- Der lokale Modus liest weiterhin ausschließlich Dateien, nie `st.secrets`. Ein versehentlich auf `local` gestellter gehosteter Betrieb findet so keinen Schlüssel.
- Doku: Secrets-Vorlage, README, CONTAINER.md und eine Schritt-für-Schritt-Anleitung für Community Cloud.

## Abnahmekriterien

- [ ] Anonyme, fremde, abgelaufene oder abgemeldete Sitzungen bauen keinen Ladeablauf auf und lesen keine Schlüssel-/Listing-Secrets.
- [ ] Freigegebener Besitzer sieht eigene Daten ohne Demo-Hinweise; Live-Kurse nur für Positionen mit Listing-Eintrag.
- [ ] Fehlender oder ungültiger `[sheets_service_account]` bzw. ungültige Listings erzeugen eine neutrale Fehlermeldung ohne Werte und keine Daten.
- [ ] Lokaler Modus greift nicht auf `st.secrets` zu; bestehende Loopback-Sperre bleibt.
- [ ] Synthetische Tests, `uv run --locked ruff check .` und `uv run --locked pytest` bestanden.

## Abhängigkeiten

- #32 (Besitzerprüfung), #66/#68 (lokaler Ladeablauf und Listings), #19 (Cache/Backoff)
- Für den echten Betrieb: #31 und #34 (Besitzerschritte)

Keine echten Bestände, Listings, Schlüssel oder Kennungen in Code, Tests, Logs, Issues oder PRs.
